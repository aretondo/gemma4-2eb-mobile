# Gemma 4 Good: Resilient Offline Medical Triage & Structured Digitization

## 💡 The Inspiration & The Problem
In remote regions, disaster zones, or off-grid clinical settings (such as deep riverine areas in Brazil), stable internet is an absolute luxury. Healthcare professionals struggle to maintain structured patient records, and the lack of immediate, on-site access to clinical protocols can cost lives.

**Gemma 4 Good** was designed as an autonomous, offline-first digital scribe. It runs completely local on mobile, combining Google's **Gemma 2B** via **LiteRT**, on-device **ML Kit OCR**, and a lightweight local **RAG (Retrieval-Augmented Generation)** pipeline. It proves that edge AI is a massive equalizer in humanitarian crises.

---

## 🏗️ Technical Architecture & Core Features

### 1. Local Brain (Gemma 2B via LiteRT)
*   **Engine:** Google LiteRT (formerly TensorFlow Lite).
*   **Model:** Gemma 2B Effective (approx. 2.6GB), optimized for mobile CPU/GPU execution.
*   **Key Advantage:** 100% offline processing, ensuring full availability in the field and complete data privacy for sensitive medical records.

### 2. Local RAG (Retrieval-Augmented Generation) & Dynamic Sync
*   **Mechanism:** Kotlin `KnowledgeManager`.
*   **Pipeline:** 
    1. Technical manuals and WHO protocols (TXT/MD) are uploaded to a Streamlit backend and split into 800-character chunks with a 100-character overlap.
    2. The Android app syncs and stores the database locally on the device when connected.
    3. User queries trigger a high-speed keyword relevance search offline, injecting matching context chunks into the prompt.
*   **Outcome:** Answers strictly grounded in verified medical protocols, complete with visual source citations (e.g., `Sources: [filename]`) beneath the chat bubble.

### 3. Two-Stage Intent Parsing (Cactus Concept)
To prevent the model from losing track within long conversation contexts, we implemented a hybrid inference pipeline:
*   **Stage 1 (Classification):** A micro-inference identifies whether the user wants to execute an operational command (e.g., "mark as ready") or make a clinical query.
*   **Stage 2 (Execution):** The system instantly executes system actions or proceeds to generate a detailed technical response.

### 4. Computer Vision & Multi-Image OCR
*   **OCR:** Integrated with Google ML Kit to extract structured data from prescriptions and medical reports.
*   **Multi-Page Support:** Allows attaching multiple photos to a single clinical case, stored as structured JSON.
*   **Encoding:** Automated conversion of captured images to Base64 for clean and structured API synchronization when internet returns.

## 📱 Material 3 User Interface & Clean Visuals
*   **My Files:** A beautiful file management dashboard featuring Material 3 cards and color-coded status badges (`PENDING`, `READY`, `SYNCED`).
*   **Fluid Chat:** Support for native Markdown formatting (bold text, bullet points) and persistent conversation history per document.
*   **Invisible Tool Use:** Operational tags (e.g., `[SET_STATUS:READY]`) generated by Gemma are filtered out by a robust Android Regex, updating the local database silently without cluttering the chat view.
*   **Hybrid Synchronization:** A single "Sync" button that updates the local knowledge base, fetches updated system prompts, and uploads processed cases to the FastAPI server.

## 🛠️ Technology Stack
*   **Mobile:** Kotlin, Jetpack Compose, LiteRT, ML Kit.
*   **Backend:** Python, FastAPI, Streamlit, OkHttp.
*   **Data:** JSON Local Persistence, Base64 Image Encoding.

## 🔮 The Vision: Scalability & Global Resilience
This POC demonstrates that edge AI can scale to address countless off-grid humanitarian challenges:
*   **Crisis Response:** Dynamically push localized protocols based on GPS location (e.g., active outbreaks, specific regional fauna like snakes/spiders).
*   **On-Device Psychological Support:** Deploying WHO-based *Psychological First Aid* (PCP) for local disaster-relief teams operating under heavy stress.
*   **Offline Education:** A student in a remote area during a river drought can have an offline AI tutor to guide their learning, utilizing the same LiteRT RAG infrastructure.
